# Эмулятор UNIX-подобной оболочки — вариант № 9

Учебный проект по дисциплине «Конфигурационное управление». Консольная
программа на C++17 принимает команды с клавиатуры или из сценария и работает
с виртуальной файловой системой (VFS), загруженной из XML.

**Все изменения VFS происходят только в памяти.** Команда `cp` не создаёт
настоящие файлы на компьютере и не меняет исходный XML. После перезапуска
файловая система возвращается к состоянию, описанному в XML.

## Возможности

- Приглашение `username@hostname:~$` на основе реальных данных ОС.
- Настройки запуска `--vfs`, `--script` и команда `conf-dump`.
- Сценарии с комментариями `//`, показом команд и результатов.
- Загрузка каталогов, текстовых файлов и данных base64 из XML.
- Команды `ls`, `cd`, `pwd`, `uniq`, `cp`, `vfs-dump` и `exit`.
- Сообщения об ошибках, включая номера строк сценария.
- Автоматические интеграционные тесты.

## Требования

Для сборки нужны компилятор C++17 и `make`. Для тестов — Python 3
со стандартной библиотекой `unittest`; сторонние пакеты не нужны.

Код использует POSIX-функции из `<pwd.h>` и `<unistd.h>` и рассчитан
на macOS/Linux. Нативная сборка в Windows без адаптации не поддерживается.
В Windows можно использовать Linux-среду WSL с инструментами сборки.

На Mac инструменты командной строки Apple устанавливаются командой:

```bash
xcode-select --install
```

## Быстрый запуск на Mac

### Первое скачивание

Введите в обычном приложении **«Терминал»**:

```bash
git clone https://github.com/Daylolot/ConfUpravPrakt1.git
cd ConfUpravPrakt1
make
./emulator --vfs examples/commands.xml
```

### Если проект уже скачан

Перейдите в его папку: введите `cd` с пробелом, перетащите папку проекта
из Finder в терминал и нажмите Enter. При скачивании ZIP папка может
называться `ConfUpravPrakt1-main`. Затем выполните:

```bash
make
./emulator --vfs examples/commands.xml
```

Сообщение `emulator is up to date` означает, что программа уже собрана.
После изменения исходников снова выполните `make`.

### Работа внутри эмулятора

После запуска появится приглашение вида `user@computer:~$`.
Теперь можно вводить команды эмулятора:

```text
ls
cd docs
pwd
uniq repeat.txt
cp repeat.txt backup.txt
ls
exit
```

`exit` возвращает управление обычному терминалу Mac.

**Не путайте два режима:** `make`, `bash examples/config.sh` и строку
`./emulator --vfs ...` вводят в обычном терминале. Команды `ls`, `pwd`,
`uniq` и другие из таблицы ниже — внутри эмулятора.

## Параметры запуска

```bash
./emulator [--vfs file.xml] [--script commands.txt]
```

| Параметр | Назначение | Пример |
| --- | --- | --- |
| `--vfs` | Путь к настоящему XML-файлу с описанием VFS | `--vfs examples/files.xml` |
| `--script` | Путь к настоящему файлу команд | `--script examples/config.txt` |

Оба параметра необязательны, порядок не важен. Повторные и неизвестные
параметры, а также параметры без значения отклоняются. При запуске выводятся
`vfs_path` и `script_path`.

```bash
./emulator --vfs examples/files.xml --script examples/config.txt
```

`--vfs` и `--script` передаются после `./emulator` при запуске.
Они не являются командами внутри работающего эмулятора.

Без `--vfs` доступны `conf-dump` и `exit`; команды, требующие VFS,
сообщают `no VFS loaded`.

## Команды

Квадратные скобки обозначают необязательный аргумент — вводить их не нужно.

| Команда | Действие |
| --- | --- |
| `ls [путь]` | Содержимое каталога или имя файла; без пути — текущий каталог |
| `cd [путь]` | Переход в виртуальный каталог; без пути — в `/` |
| `pwd` | Текущий виртуальный путь |
| `uniq файл` | Удалить соседние повторы строк |
| `uniq -c файл` | Число строк в каждой группе |
| `uniq -d файл` | Только группы с повторами |
| `uniq -u файл` | Только группы из одной строки |
| `cp источник назначение` | Копирование файла |
| `cp -r источник назначение` | Копирование каталога со всем содержимым |
| `conf-dump` | Настройки в формате ключ-значение |
| `vfs-dump` | Дерево VFS и размеры файлов в байтах |
| `exit` | Завершение работы |

### Пути и ограничения

- `/docs/repeat.txt` — абсолютный виртуальный путь; `repeat.txt` — относительный.
  `.` означает текущий каталог, `..` — родительский.
- `cd` меняет только виртуальный каталог, настоящая рабочая папка ОС не меняется.
- `uniq` обрабатывает только соседние повторы. Файл обязателен;
  сочетания ключей и чтение из stdin не поддерживаются. Файлы с нулевым байтом отклоняются.
- Если назначение `cp` — каталог, копия помещается внутрь с именем источника.
  Существующий файл назначения перезаписывается. Слияние каталогов не поддерживается.
- Копирование корня, файла в самого себя и каталога внутрь себя запрещено.
- Ввод разделяется по пробельным символам. Кавычки, имена с пробелами,
  конвейеры, перенаправления и запуск внешних программ не поддерживаются.

Путь `examples/files.xml` указывает на настоящий файл компьютера.
Путь `/docs/repeat.txt` указывает на файл внутри VFS.

## Сценарии и демонстрации

Файлы `.txt` содержат по одной команде эмулятора на строку.
Пустые строки и строки, начинающиеся после пробелов с `//`, пропускаются.
Комментарии после команды и блоки `/* ... */` не поддерживаются.

Команда выводится вместе с приглашением, затем показывается результат.
При ошибке выводятся путь сценария и номер строки; выполнение продолжается.
`exit` завершает программу. Если сценарий закончился без `exit`,
программа переходит к интерактивному вводу.

Запускайте из корня проекта в обычном терминале:

| Проверка | Команда |
| --- | --- |
| Настройки и ошибки команд | `./emulator --vfs examples/files.xml --script examples/config.txt` |
| Загрузка и дерево VFS | `./emulator --vfs examples/deep.xml --script examples/vfs.txt` |
| Навигация и режимы uniq | `./emulator --vfs examples/commands.xml --script examples/commands.txt` |
| Копирование и его ошибки | `./emulator --vfs examples/commands.xml --script examples/copy.txt` |

**В демонстрационных сценариях есть намеренные ошибки**, например
`bad-command` и `exit extra`. Сообщения о них — ожидаемая часть демонстрации.

Скрипты `.sh` выполняет настоящая оболочка ОС:

```bash
bash examples/config.sh
bash examples/errors.sh
bash examples/vfs.sh
```

- `config.sh` — разные параметры запуска и их порядок.
- `errors.sh` — ошибочные параметры, отсутствующие файлы и неправильный XML.
- `vfs.sh` — минимальная VFS, несколько файлов и глубокая вложенность.

Эти скрипты показывают поведение. Автоматические проверки результата находятся в `tests/`.

### Коды завершения

| Код | Значение |
| --- | --- |
| `0` | Обычное завершение без ошибок сценария |
| `1` | Ошибка загрузки VFS/сценария, чтения сценария или одной из его команд |
| `2` | Неправильные параметры запуска |

Ошибки команд, введённых вручную, выводятся на экран, но сами по себе
не меняют итоговый код завершения.

## Формат VFS

Используется ограниченный формат XML: корень `<vfs>`, каталоги `<dir>`
и файлы `<file>`. Имена внутри одного каталога должны быть уникальными.

```xml
<?xml version="1.0"?>
<vfs>
  <file name="readme.txt">Hello &amp; welcome!</file>
  <file name="raw.bin" encoding="base64">AAEC/w==</file>
  <dir name="docs">
    <file name="notes.txt">First line.</file>
  </dir>
</vfs>
```

Поддерживаются XML-сущности `&amp;`, `&lt;`, `&gt;`, `&quot;`, `&apos;`
и комментарии XML. Для двоичных данных указывается `encoding="base64"`.
Парсер рассчитан на этот формат, а не на произвольный XML.

| Файл | Назначение |
| --- | --- |
| `examples/minimal.xml` | Минимальная VFS |
| `examples/files.xml` | Несколько файлов, XML-сущности и base64 |
| `examples/deep.xml` | Вложенность home/student/projects |
| `examples/commands.xml` | Данные для навигации, uniq и cp |
| `examples/invalid.xml` | Намеренно неправильный XML |

## Автоматические тесты

```bash
make test
```

Команда собирает программу при необходимости и запускает 22 тестовых метода
из `tests/test_emulator.py` средствами стандартной библиотеки Python `unittest`.

Проверяются навигация, режимы `uniq`, копирование и перезапись, ошибки команд
и параметров, загрузка XML, распознавание двоичного файла, комментарии и номера
строк сценария. Отдельный тест сравнивает XML до и после `cp` и проверяет,
что копия отсутствует после перезапуска.

При успехе вывод заканчивается `OK`; при провале проверки команда возвращает
ненулевой код. Временные сценарии создаются вне репозитория и удаляются.
Путь к Python при необходимости можно указать через `make test PYTHON=/путь/к/python3`.

## Этапы разработки

| Этап | Результат |
| --- | --- |
| 1. REPL | Консольный ввод, данные ОС, парсер, ошибки, заглушки ls/cd и exit |
| 2. Конфигурация | --vfs, --script, conf-dump, сценарии и диагностика |
| 3. VFS | XML/base64 в памяти, vfs-dump и примеры файловых систем |
| 4. Основные команды | Рабочие ls/cd, добавление pwd и uniq |
| 5. Дополнительные команды | cp и cp -r, изменения только в памяти |

Этапы сохранены отдельными коммитами. Заглушки первого этапа доступны
в его историческом коммите; в текущей версии `ls` и `cd` уже работают с VFS.
Перенос исходников в `src/` и добавление `tests/` оформлены следующими коммитами.

## Частые проблемы

| Сообщение | Что сделать |
| --- | --- |
| `zsh: no such file or directory: ./emulator` | Перейти в папку проекта через cd и выполнить make |
| `--vfs: command not found` | Выйти через exit; в обычном терминале ввести всю строку ./emulator --vfs ... |
| `ls: .: no VFS loaded` | Перезапустить с --vfs examples/commands.xml |
| `script: cannot open ...` или `vfs: cannot open file: ...` | Проверить текущую папку и путь |
| `script: ...:N: command failed` | Проверить строку N; в примерах ошибка может быть намеренной |

`make clean` удаляет собранную программу. Исходники, сценарии и XML сохраняются.
