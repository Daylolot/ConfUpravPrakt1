# Эмулятор командной строки — вариант 9

macOS, `g++` (C++17), `make`:

```bash
make
./emulator --vfs examples/deep.xml --script examples/vfs.txt
./examples/config.sh
./examples/errors.sh
./examples/vfs.sh
./emulator --vfs examples/commands.xml --script examples/commands.txt
./emulator --vfs examples/commands.xml --script examples/copy.txt
```

Этап 1: REPL, приглашение из данных ОС, заглушки `ls`, `cd`, команда `exit`.
Этап 2: параметры `--vfs`, `--script`, команда `conf-dump`, стартовый скрипт с комментариями `//`.
Этап 3: XML VFS загружается в память; `vfs-dump` показывает её дерево.
Этап 4: `ls`, `cd`, `pwd`, `uniq` работают с VFS в памяти. `cd` меняет виртуальную папку, приглашение показывает её путь; физическая папка компьютера не меняется.
Этап 5: `cp ИСТОЧНИК НАЗНАЧЕНИЕ` копирует файл, `cp -r ИСТОЧНИК НАЗНАЧЕНИЕ` копирует папку со всем содержимым. Существующий файл назначения перезаписывается; копирование папки поверх существующей папки с тем же именем выдаёт ошибку. Исходный XML не изменяется: после нового запуска копий в VFS нет.

`ls [путь]` выводит содержимое папки или имя файла, `cd [путь]` переходит в папку (`cd` без аргумента — в `/`), `pwd` показывает путь.
`uniq файл` убирает **соседние** одинаковые строки; `-c` показывает их число, `-d` оставляет повторы, `-u` оставляет только уникальные строки. Имя файла обязательно: стандартный ввод занят командами REPL.

Формат XML: корень `<vfs>`, внутри `<dir name="...">` и `<file name="...">текст</file>`.
Для двоичного файла укажите `encoding="base64"`; XML сущности `&amp;`, `&lt;`, `&gt;`, `&quot;`, `&apos;` поддерживаются. Имена внутри папки уникальны.
Если `--vfs` не задан, работать без VFS можно, но `vfs-dump` сообщает об ошибке.

`examples/minimal.xml`, `files.xml`, `deep.xml` показывают три варианта VFS.
`examples/invalid.xml` проверяет ошибку формата. Скрипт `vfs.sh` запускает разные варианты VFS, а `errors.sh` проверяет отсутствие файла и ошибки XML.
Ошибки внутри `vfs.txt` намеренные: скрипт продолжает работу и показывает номер строки.
`examples/commands.xml` и `commands.txt` проверяют команды этапа 4, относительные и абсолютные пути, `..`, режимы `uniq` и ошибки. Ошибки в нём тоже намеренные.
`examples/copy.txt` проверяет варианты `cp`, результат через `ls`, `uniq`, `vfs-dump` и намеренные ошибки. Стартовые скрипты с ошибками завершаются кодом 1, сохраняя номера ошибочных строк.

Сценарий этапа 1: `./emulator`, затем `ls`, `cd docs`, `ls a b`, `unknown`, `exit`.
